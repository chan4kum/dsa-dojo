# D03 · Hashing and frequency maps

Use a hash table to make repeated lookups cheaper. Start by deciding what makes two keys equal, what information each entry stores, and when an entry can be discarded. See [Hashing](01-hashing.md) for the Dojo templates.

## Guided walkthrough

1. **D03.01 · Hash functions.** A hash maps a key to a numeric value. A simple table with four buckets can choose index h(key) mod 4. With h(key)=key, 1 and 5 both choose bucket 1. Equal keys must hash equally, and unequal keys can hash equally.
2. **D03.02 · Collisions.** Reaching a bucket finds candidates. A key equality check identifies the intended entry. In the previous example, a lookup for 5 must skip stored key 1 even though the bucket matches.
3. **D03.03 · Open addressing and chaining.** Chaining holds multiple entries per bucket. Open addressing uses a probe sequence across slots in the same table. In a linear-probe table with keys 1 and 5 in slots 1 and 2, clearing slot 1 as if it had always been empty can hide key 5. Tombstones or an appropriate repair of the probe chain preserve lookup.
4. **D03.04 · Load factor.** With n entries and m buckets or slots, load factor is n/m. Six entries in eight slots give 0.75. Collision cost also depends on distribution and the collision strategy. Resizing typically reassigns entries, so account for rebuild work and temporary storage.
5. **D03.05 · Dictionaries.** A dictionary can hold an index, count, or other state per key. Counting characters in “aba” produces a→2 and b→1. State the cost of hashing and comparing keys. Expected constant lookup under ordinary conditions does not guarantee a fixed number of steps for every input.
6. **D03.06 · Two Sum.** Before processing index i, store values from indices strictly before i. Look up target minus the current value before inserting it. For [3,3] and target 6, the first 3 is stored and the second completes the pair. A singleton 3 cannot pair with itself.
7. **D03.07 · LRU and LFU.** LRU evicts the least recently used entry. LFU evicts a least frequently used entry under a stated tie rule and counting window. With capacity two, after A,A,A,B,B,C, LRU evicts A because B was touched later. Plain LFU evicts B because A has three accesses and B has two.

### Worked case

In [Two Sum](01-hashing.md), try [4,2,7] with target 9. At index 0, look for 5 and store 4. At index 1, look for 7 and store 2. At index 2, look for 2 and return indices [1,2]. Pair enumeration has quadratic worst-case work and uses constant auxiliary space. The hash scan has expected linear work with O(n) auxiliary entries under the usual hash and key-cost assumptions.
